# Проверка обновлений Android

Начиная с 0.24.16 приложение проверяет последний опубликованный стабильный выпуск
GitHub при открытии/возврате в приложение, не чаще раза в 24 часа. В настройках
можно проверить вручную. Неудачная попытка также ограничивает автоматические
повторы. Фоновый сервис и системные уведомления при закрытом приложении не нужны.

Карточка на обзоре предлагает скачать, отложить на сутки или пропустить конкретный
versionCode. Ручной раздел позволяет открыть найденный выпуск даже после пропуска.
Проверка не управляет DPI, VPN и прокси; ошибки отображаются только в настройках.
Скачивание открывает страницу выпуска, установка требует действий пользователя.

## Публикация следующей версии

1. Увеличить Android versionCode/versionName, собрать и проверить подписанный APK.
2. Создать короткий UTF-8 файл с изменениями и выполнить:

```powershell
python scripts/create-update-manifest.py --apk <APK> --build-tools <SDK/build-tools/36.0.0> --tag android-v0.24.16 --notes <notes.txt>
```

3. В черновик выпуска загрузить APK, `local-route-update.json` и соответствующие
   исходники, затем опубликовать выпуск как стабильный. Не менять метаданные вручную:
   скрипт извлекает пакет, версию, minSdk и сертификат из проверенного APK.

Файл описывает один пакет и один APK. Community/preview/RuStore не взаимозаменяемы.
Клиент принимает только больший versionCode с совпадающими пакетом и текущим
сертификатом, подходящим minSdk, ожидаемым GitHub URL и существующим APK-asset.
Проверяются размер и SHA-256 метаданных против digest GitHub, когда он доступен.
Черновики, prerelease и выпуски без метаданных не предлагаются. В частности,
старые сборки до 0.24.16 не научатся проверять обновления автоматически.

Приложение не скачивает APK само и не проверяет его байты на устройстве. Финальную
проверку устанавливаемого пакета/подписи выполняет Android при ручной установке.
Ротация сертификата и несколько подписантов требуют отдельного расширения схемы.

Проверка использует публичный GitHub API без токенов. Ключи подключения, профили,
журналы и идентификаторы устройства не передаются; GitHub видит обычный сетевой
запрос. Весь ответ ограничен по размеру, редиректы разрешены только на домены GitHub,
сетевые операции выполняются вне основного потока.
