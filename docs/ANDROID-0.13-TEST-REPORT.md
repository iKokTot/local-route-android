# Android 0.13.0 — проверка 16 октября 2026

Ветка android-mvp. Изменения и APK сохранены локально; публикация, push,
отправка в RuStore/Telegram/MAX и изменения серверов не выполнялись.

## Реализовано

Telegram: встроенное MIT-ядро tg-ws-proxy-rs 2.5.4, локальный MTProto listener
127.0.0.1:1443, прямой WebSocket/TLS к Telegram, постоянный зашифрованный секрет,
foreground-уведомление с остановкой, добавление прокси через tg://proxy.
Кнопка проверки требует ответа resPQ с исходным nonce; проверка не входит в аккаунт.
Списки публичных прокси и внешние CF-прокси отключены; сервер Local Route не нужен.

VLESS: исправлено отсутствующее ACCESS_NETWORK_STATE, обработка TunOptions,
передача интерфейсов и определение владельца соединений, DNS bootstrap и DoH,
защита исходящих сокетов, запрет использования собственного TUN как uplink,
закрытие ресурсов при ошибке. Для Android выбран стек gvisor; mixed на этом
эмуляторе создавал TUN, но не пропускал TCP. Сохранение ошибочной новой ссылки
больше не запускает старый профиль. WireGuard исключён из кода/сборки/манифеста.
Исправлен перенос заголовков на узком экране.

## Фактические результаты

Сборка testDebugUnitTest / assembleDebug / assembleRelease успешна.
11 unit-тестов: 0 failures / 0 errors.
Эмулятор Medium_Phone_API_37.0, x86_64: `OK (6 tests)`, 38.432 секунды.

1. Выбранное приложение с отдельным UID получает HTTP-ответ через реальный TUN
   и тестовый VLESS/TCP-сервер. Без VPN такой ответ недоступен.
2. WebSocket VLESS в режиме всего устройства передаёт тот же запрос.
3. TLS + WebSocket и DNS через DoH внутри VLESS передают запрос по имени.
   TLS-сертификат fixture самоподписанный; allowInsecure включён только в тестовой ссылке.
4. Невыбранное приложение не достигает fixture через активный VPN.
5. Telegram JNI-прокси запускается, получает настоящий resPQ от Telegram через
   WebSocket, останавливается и повторяет проверку после нового запуска.
6. Локальный ByeDPI-режим по-прежнему запускается и передаёт HTTPS к example.com
   из отдельного тестового приложения через его VPN.

Подписанный release APK отдельно установлен на эмулятор. Через интерфейс
запущен Telegram-прокси и нажата кнопка проверки: получено
«Telegram ответил через WebSocket». Foreground-уведомление и кнопка остановки
присутствуют, журнал аварий после проверки пуст. Скриншот сохранён рядом с APK.

## Что эти тесты не подтверждают

Все тесты выполнены на эмуляторе, не на ARM-телефоне пользователя.
Не проверены конкретная пользовательская VLESS-ссылка, Reality/gRPC/HTTP Upgrade,
смена мобильной сети и ограничения энергосбережения прошивок.
Нет входа в Telegram-аккаунт: пользовательские чаты, загрузки фото/видео, все DC
и звонки необходимо проверить на телефоне. Эмулятор не воспроизводит DPI
провайдера или белые списки. Доступ к WebSocket-точкам Telegram должен сохраняться.

Для воспроизведения: scripts/vless-test-fixture.py, модуль networkprobe,
app/src/androidTest/.../NetworkIntegrationTest.kt; команды приведены в README.
networkprobe и instrumentation APK не входят в пользовательский release APK.
