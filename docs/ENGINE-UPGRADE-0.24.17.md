## Совместимость

- Новый HEV регистрирует JNI-методы с результатом Boolean и требует IsRunning.
  Kotlin-объявления обновлены. Отказ запуска/остановки больше не игнорируется.
- ByeDPI 0.17.3 (`7efde1b1296eaaa187b70e951894dde17527489c`) был собран и проверен,
  но два полных прогона выявили тайм-аут HTTPS после переключения режимов.
  Отдельный запуск проходил. В контрольном APK заменили только libbyedpi.so
  на прежнюю 0.13, оставив остальные четыре обновлённых компонента: этот же HTTPS
  сценарий прошёл в полном сетевом прогоне. Кандидат отклонён; в итоговой сборке
  сохранены прежний JNI/парсер и рабочая строка. Точная причина различия между
  версиями не установлена. CLI-выход, listener и transparent-режим из строки запрещены.
- Из Android-адаптеров libbox убран удалённый upstream метод useProcFS.
- Telegram использует прежний JNI-контракт; 2.7.0 включает HTTP/2 для медиа через CF
  с upstream-возвратом к WebSocket. Прокси остаётся самостоятельным, не переключается
  автоматически на VLESS/DPI. Обновлены тесты, всё ещё ожидавшие прежнюю маршрутизацию.
- OpenFlux собран заново для arm64-v8a, armeabi-v7a, x86_64. Сборка проверяет ревизию
  исходников и оставляет revision stamp, который требует Gradle. Случайно упаковать
  прежние helper-бинарники после смены закреплённой версии больше нельзя.
- Собирается только библиотека HEV, без ненужного CLI-бинарника; native make использует
  четыре параллельные задачи. Это оптимизация сборки, не заявление об ускорении сети.

## Лицензии

Проверены контрольные суммы скачанных APK/AAR. Обновлены уведомления для 182 Rust
зависимостей Telegram. Добавлены тексты лицензий 37 Go-модулей OpenFlux и Go runtime;
Go modules verified. Скрипты аудита находятся в scripts/; GPL/MIT/BSD notices сохранены.

## Границы проверки

Эмулятор API 37, x86_64. ARM-библиотеки компилируются, физическое ARM-устройство
в этот прогон не входит. Локальный тестовый сервер VLESS проверяет TCP, WebSocket,
TLS и DNS; независимый тестовый UID создаёт запросы через настоящий Android TUN.
Проверяются исключения, повторные старты/остановки, совместная работа и потеря сети.
Telegram-проверки получают публичный resPQ, не читают сообщения/аккаунт пользователя.
OpenFlux проверяется через локальный зашифрованный выходной узел и HTTP/UDP. Работа
через Yandex/Telemost в ограниченной мобильной сети и реальная скорость не доказаны.

Первый прогон обнаружил старые ожидания маршрута Telegram и тайм-аут HTTPS.
Тесты маршрута обновлены с сохранением реальных MTProto-запросов. В HTTPS-тест добавлен
контроль доступности того же сайта до включения DPI. Отдельный повтор проходил,
но полная последовательность снова выявила проблему — поэтому выполнено сравнение
библиотек и сохранён старый ByeDPI, а не ослаблена проверка HTTPS.
Итоговые результаты полного прогона записываются в описание выпуска.

У старого ядра в одном прогоне оказался недоступен сам внешний сайт до включения
DPI. Поэтому внешний тест выбирает доступный HTTPS-узел из фиксированного списка
и сравнивает запросы до/после DPI к тому же узлу; проверяет TLS/HTTP, а не конкретный
текст страницы. Если все узлы недоступны без VPN, тест явно пропускается как зависимый
от внешней сети. В финальном прогоне сетевые 21 тест прошли, включая этот HTTPS-тест.
Это не доказывает, что тайм-ауты кандидата 0.17.3 вызваны именно его кодом; выпуск
сохраняет известное рабочее ядро консервативно, поскольку кандидат не прошёл gate.

Финал: 72 модульных теста, 21 сетевой тест, 1 OpenFlux, 20 автоматических UI и
5 тестов обновлений — без ошибок. Ещё один ручной Chrome/ChatGPT-сценарий требует
явного запуска с профилем владельца и не выполнялся. Медиа CF HTTP/2 получило resPQ;
публичная строка подключения транспорта сохранена отдельно от секретов.
