# Local Route — Android MVP

Отдельное Android-приложение Local Route. Код Windows-версии в этот подпроект не
переносится и не изменяется.

## Текущая версия 0.22.0

«Настроить» открывает настройки текущего режима: DPI / TG / VLESS. Внутри —
только его параметры, плитка и диагностика. «Все настройки» открывает общий
список. Компактная панель ТГ / МАКС / GitHub есть в настройках и «О приложении».
На первом посещении каждой вкладки показан короткий помощник, который скрывается
после «Понятно» и не появляется снова. Общее знакомство и повторная справка сохранены.

Пользовательские исключения теперь только для VLESS: при DPI без сервера список
не применяется. Базовый каталог расширен до 22 проверенных Android-пакетов:
[источники и ограничения](docs/VLESS-EXCLUSIONS-SOURCES.md). Ручной список не
сбрасывается; добавить новые пункты можно через «Добавить рекомендованные».

### Предыдущее оформление 0.21

UI-only обновление после подтверждённой пользователем работы 0.20. Сетевые
сервисы, компиляторы маршрутов и протоколы не менялись. На трёх основных
вкладках только состояние и основные действия. Кнопка запуска/остановки
закреплена над навигацией и не уезжает при прокрутке. Настройки открываются
отдельно: сервер, сервисы DPI, приложения без VPN, плитки, диагностика, справка.
Первое знакомство показывается автоматически один раз; повторно — через
«Настройки → Как пользоваться». Рабочие режимы не останавливаются при переходах.

### Изменения сетевой части в 0.20 (сохранены без изменений)

После сообщения о неработоспособности 0.19 на телефоне упрощены отдельные режимы.
VLESS без DPI использует прежний VlessConfigCompiler, без package/sniff-правил.
DPI без сервера направляет обычный интернет в локальный SOCKS, не полагаясь на
определение Android UID или SNI. Выбор сервисов разделяет маршруты только при
одновременно включённых DPI/VLESS. Локальная сеть остаётся прямой.
Это исправления выявленных рисков, а не подтверждение устранения конкретной
ошибки на телефоне: для неё нужны повторная проверка и свежий журнал.

В разделе «Без VPN» можно выбрать установленные приложения, которые полностью
исключаются из Android TUN (в обоих режимах, включая DNS). По умолчанию добавлены
известные пакеты банков, Ozon и Wildberries; разные версии банков могут иметь
другой пакет — проверьте список на своём устройстве. Список хранится локально.
Изменение применяется сохранением и кратким переподключением активного VPN.
При системной блокировке соединений без VPN исключения не смогут выйти в сеть.
Исключения относятся к приложениям, а не сайтам банка в общем браузере.

«Диагностика VPN» доступна на DPI/серверной вкладках независимо от состояния.
Ошибки ядра сохраняются только в памяти (до 100 строк), ссылку/UUID скрываем.
Журнал можно самостоятельно скопировать; автоматической отправки нет.

Три вкладки: **DPI**, **TG**, **VLESS**. Проверка локального DPI находится внутри
вкладки DPI. VLESS включается для всего устройства, выбора приложений нет;
старая настройка allowlist больше не применяется. На Android 10+ DPI и VLESS
могут работать одновременно: выбранные сервисы идут локально, остальные — через сервер.
Каждая кнопка остановки выключает только свой режим.

В быстрые настройки Android можно добавить три отдельные плитки: **DPI**
(сохранённая локальная стратегия), **TG Proxy** (постоянный локальный прокси),
**VLESS** (сохранённая ссылка). Повторное нажатие останавливает соответствующий
режим. При отсутствии VPN-согласия/ссылки/разрешения уведомлений открывается
нужная вкладка приложения. У плиток разные значки (молния / самолёт / щит),
чтобы их можно было различать даже в компактной шторке без подписей.
В уведомлениях — одноцветный знак Local Route; фон иконки приложения светлый мятный.

TG использует обычную цепочку ядра как desktop: WebSocket, затем MTProto TCP.
В 0.13 были ошибочно закреплены только WS и IP для всех DC, что убирало fallback.
В текущей версии доступны сторонние CF-ретрансляторы из списка Flowseal;
их доступность зависит от сети, они не принадлежат Local Route.
Если активен DPI, TG использует его локальный SOCKS; при VLESS — отдельный
аутентифицированный SOCKS-вход libbox на loopback. Он доступен только с временным
секретом, не сохранённым в логах. Смена режима автоматически перезапускает TG
с прежним MTProxy-секретом, повторно добавлять прокси в Telegram не требуется.

«Порт открыт» означает только работающий listener. Доступ к Telegram проверяется
автоматически по resPQ, и неуспех отдельно отображается как «Нет связи».
Никакой локальный режим не гарантирует доступ к заблокированным IP; в этой
ситуации нужен доступный VLESS-сервер пользователя.

## Архитектурное и лицензионное решение (зафиксировано до реализации)

`LOCAL_DPI` строится по схеме ByeDPIAndroid: Android `VpnService` создаёт только
локальный TUN-интерфейс, `tun2socks` направляет трафик устройства в локальный
SOCKS5-процесс, а DPI-стратегия применяется локальным процессом. Внешнего
прокси, VPN-сервера и передачи телеметрии в этом режиме нет. IP пользователя не
скрывается и трафик не шифруется дополнительно.

Вдохновляющий проект [ByeDPIAndroid](https://github.com/dovecoteescapee/ByeDPIAndroid)
— GPL-3.0 и использует ByeDPI (MIT) и hev-socks5-tunnel (MIT). Android-подпроект
Local Route поэтому выпускается под GPL-3.0-or-later. Вендорены как Git
submodules фиксированные исходники ByeDPI и hev-socks5-tunnel; JNI-граница
ByeDPI собрана по аудированному GPL-референсу актуального `master` ByeDPIAndroid
(`43db0955de687d43f9473374dc7c5548eaa55359`) и версии 1.2.0, а `NativeTunnelBridge` остаётся
точкой подключения tun2socks. Notices, SHA и ссылки на исходники находятся в
`app/src/main/assets/licenses/`.

`SECURE_TUNNEL` остаётся только будущим контрактом архитектуры: отдельного
WireGuard-режима, его библиотеки и экранов в текущей сборке нет. Приложение не
получает каталогов серверов, не создаёт серверы и не отправляет конфигурации.

## Telegram: архитектурное и лицензионное решение

Встраиваем только JNI-ядро `tg-ws-proxy-rs` 2.5.4 (MIT), commit
`a796423e561c558fcc7ff4ecfe3e5853a434ce84`. Это Rust-порт Flowseal/tg-ws-proxy.
Нативные библиотеки берутся из официального universal APK с фиксированным SHA-256;
его интерфейс и Android-приложение не включаются. JNI-класс сохраняет upstream
имя, поскольку оно является частью бинарного контракта. Полные исходники и
Cargo.lock доступны по закреплённому commit, notices поставляются в APK.
Прокси слушает только 127.0.0.1:1443, использует постоянный локальный секрет,
не требует VpnService и работает в foreground-сервисе. Запрещаем автоматическую
загрузку исполняемого кода. Для CF-ретрансляторов ядро получает список доменов
Flowseal с резервным встроенным списком; это внешняя конфигурация и сторонняя
инфраструктура. WebSocket и TCP направляются к Telegram.
Проверка отправляет MTProto req_pq_multi и требует ответа resPQ с тем же nonce.
Она не подтверждает работу звонков или всех медиа. Сам пакет Local Route
исключён из TUN; TGWs явно подключается к SOCKS активного DPI/VLESS-движка,
чтобы исключение собственного пакета не оставляло Telegram вне выбранного пути.

## Решение для VLESS

VLESS на Android реализуется не как отдельный исполняемый файл из sandbox, а
через Android-библиотеку `libbox` 1.14.0 — GPL-3.0-обвязку `sing-box`,
того же сетевого движка, который уже применяется в Windows-версии для
избирательной VLESS-маршрутизации. Конкретный AAR фиксируется SHA-256 и
загружается Gradle только для сборки; бинарник и VLESS-ключи не добавляются в
репозиторий.

VLESS-ссылка пользователя хранится в зашифрованном хранилище Android. После
явного включения интернет устройства направляется в VLESS-TUN, кроме
выбранных локальных сервисов при одновременно включённом DPI и
сокетов самого движка. Исходящие сокеты движка защищены от повторного
попадания в TUN, а смена Wi-Fi/мобильной сети передаётся движку через системный
`ConnectivityManager`. Это необходимо для корректной маршрутизации на Android.
Статус «подключён» означает, что TUN и движок запущены; он не является ложным
обещанием доступности каждого сайта в конкретной сети.
Для Android используется userspace-стек `gvisor`: скопированный с desktop
`mixed` не пропускал TCP в эмуляторе. Системный монитор выбирает только физические
сети (`NOT_VPN`), поэтому созданный TUN не становится собственным uplink.
DNS известных доменов выбранных DPI-сервисов идёт напрямую; остальной DNS
при VLESS идёт через DoH внутри туннеля. Это правило доменов, не гарантия
локального DNS для всех неизвестных адресов выбранного приложения.
Адрес самого сервера разрешается через DNS исходной сети.

## Модули пакетов

* `core` — профили, режимы и диагностика.
* `localdpi` — адаптер локального ByeDPI SOCKS-движка и его состояние.
* `tunnel` — VLESS-парсер, локальное зашифрованное хранилище, конфигурация
  `sing-box` и единый Android `CombinedVpnService` для совместной маршрутизации.
* `data` — локальные SharedPreferences для последней подтверждённой стратегии.
* корневой Compose UI — тёмные русскоязычные экраны управления и диагностики.
* `licenses` — упакованные лицензии и notices.

## Ограничения

Режим применим лишь к обычным блокировкам DPI. Он **не** заменяет полноценный
туннель в сети с разрешённым списком сайтов. Не реализуется и не обещается
«маскировка Google под Яндекс»: для HTTPS это не надёжная локальная техника.
Telegram использует отдельный WebSocket-прокси. Android потребует явного согласия на
VPN. Автозапуск после перезагрузки не реализуется.

## Функциональность

* Тёмный адаптивный интерфейс Jetpack Compose для YouTube и Discord с фирменным
  знаком desktop-версии и ссылками на Telegram/GitHub.
* Один Android-профиль на ByeDPI 13 той же зафиксированной ревизии, которую
  использует ByeDPIAndroid 1.2.0. Он основан на рабочей строке ByeDPIAndroid.
  Дополнительные пресеты будут возвращены только после реальной проверки.
* Пользовательская строка передаётся в ByeDPI без добавления скрытых флагов.
  Адрес `127.0.0.1:1080` берётся из штатных значений ByeDPI, как в
  ByeDPIAndroid. В частности Local Route больше не добавляет `--no-ipv6`.
* На первом этапе доступен один профиль, буквально совпадающий с рабочей
  строкой ByeDPIAndroid, вместо неподтверждённого набора пресетов.
* Один `CombinedVpnService` владеет TUN/gVisor и локальным ByeDPI SOCKS5.
  DPI и VLESS включаются и выключаются независимо; второй Android VPN не создаётся.
* Автоматический сетевой тест отключён: он не может доказать работу YouTube и
  давал ложные сообщения об ошибке. Экран «Проверка» открывает выбранный
  сервис при включённой защите; подтверждение — реальное воспроизведение.
* При совместном режиме выбранные YouTube/Discord направляются в локальный DPI
  по Android-пакету и известным доменам, остальное — через VLESS. Без сервера
  обычный интернет направляется в локальный DPI. Приложения в исключениях и
  локальная сеть идут напрямую. Собственный пакет исключён для предотвращения петли.
* DNS известных локальных сервисов использует DNS физической сети; остальной
  DNS при VLESS идёт через DoH в туннеле. Доступность DNS провайдера важна;
  скрытый переход локальных сервисов на сервер не выполняется.
* TUN имеет IPv4/IPv6. Определение Android-пакета требует Android 10+;
  совместное включение на Android 8/9 отключено с объяснением. В браузере
  сопоставление известных доменов не гарантирует охват всех CDN.
* Готовность ByeDPI проверяется SOCKS5-рукопожатием перед применением маршрута.
  Старые отдельные VPN-сервисы больше не зарегистрированы в манифесте.
* Постоянное Android-уведомление показывает активную стратегию и содержит
  кнопку остановки. Для Android 13+ приложение запрашивает разрешение на
  уведомления перед первым запуском.
* Кнопка «Добавить плитку в шторку» использует системный Android API. Плитка
  запускает/останавливает локальный режим; если согласия VPN ещё нет, она
  открывает приложение для его получения.
* Никакой телеметрии, аналитики или загрузки логов. Telegram может использовать
  сторонние CF-ретрансляторы со списком Flowseal; это явно описано на его экране.
* Отдельный экран «VLESS»: пользователь вставляет собственную `vless://`-ссылку
  и включает туннель всего устройства. Поддерживаются TCP, WebSocket, gRPC и HTTP Upgrade,
  с `none`, TLS или Reality. Туннель выключен до явного запуска.
  WireGuard в сборку не входит.

## Запуск и проверка на телефоне

1. Установите APK, откройте вкладку «DPI» и нажмите «Включить DPI».
2. Разрешите уведомления и подтвердите системный запрос VPN. Значок ключа — это
   локальный `VpnService`, а не внешний VPN-сервер.
3. Откройте YouTube и запустите видео. При реальном успехе откройте
   «Проверка» и нажмите «Работает — сохранить». Если сервис не работает,
   нажмите «Не работает — остановить».
4. На экране «Управление» добавьте плитку Local Route в шторку. После этого
   сохранённый профиль включается одним нажатием.
5. При проблеме откройте «Технический журнал». Он хранится только в памяти
   приложения и никуда не отправляется.

### VLESS

1. Откройте вкладку «Сервер», вставьте собственную полную `vless://`-ссылку.
2. Нажмите «Подключить VLESS» и подтвердите системный VPN, если Android
   попросит разрешение. В шторке появится постоянное уведомление с кнопкой
   остановки.
3. Проверьте выбранное приложение вручную. Если сервер, порт или транспорт
   недоступны в данной сети, локальное приложение не может исправить это само.
   При активном DPI выбранные локальные сервисы не идут в этот туннель.
4. Можно включить оба режима в любом порядке. «Выключить DPI» оставляет сервер,
   «Выключить VPN» на вкладке сервера оставляет DPI. В уведомлении есть отдельные
   действия и «Выключить всё». Смена маршрута может кратко разорвать соединения.

### Telegram

1. Откройте вкладку Telegram и нажмите «Включить Telegram-прокси».
2. Нажмите «Подключить Telegram» и подтвердите прокси в самом Telegram.
3. «Проверить соединение» проверяет настоящий ответ MTProto resPQ через
   WebSocket, без входа в аккаунт. Затем проверьте сообщения, фото и видео.
4. Local Route работает в фоне с постоянным уведомлением и кнопкой остановки.
   После остановки выберите в Telegram прямое подключение или другой прокси.
   Секрет постоянный и зашифрован Android Keystore; повторно добавлять прокси
   после обычного запуска не нужно. Отдельного сервера, рекламы и аналитики нет.

## Воспроизводимые проверки на эмуляторе

`networkprobe` — отдельное тестовое APK с собственным UID, не часть поставки.
Тесты проверяют фактический HTTP-ответ через VpnService, а не открытый порт:
TCP/WebSocket для устройства; TLS/WebSocket и DNS через DoH в туннеле;
локальные TCP/UDP выбранного пакета и независимую остановку режимов;
проверку Telegram resPQ, остановку и повторный запуск JNI-ядра.
Тестовый VLESS-сервер слушает только loopback ПК и не даёт общий доступ в Интернет.
TLS использует тестовый самоподписанный сертификат с `allowInsecure=1` только
в тестовой ссылке. Настройки пользовательского профиля тесты восстанавливают.

```powershell
# В отдельных терминалах; fixture-cert/key.pem — локальный тестовый сертификат.
python scripts/vless-test-fixture.py --cert work/fixture-cert.pem --key work/fixture-key.pem
./gradlew.bat :networkprobe:installDebug :app:installDebug :app:assembleDebugAndroidTest
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell appops set org.localroute.android ACTIVATE_VPN allow
adb shell am instrument -w -e class org.localroute.android.NetworkIntegrationTest org.localroute.android.test/androidx.test.runner.AndroidJUnitRunner
```

Эти тесты не воспроизводят блокировку конкретного провайдера и не подтверждают
все дата-центры, звонки Telegram или совместимость каждой сторонней VLESS-ссылки.

На Android-эмуляторе проверены UI, согласие VPN, device-wide TUN, SOCKS5,
повторный запуск и уведомление. Заводская версия YouTube в используемом образе эмулятора
сама остаётся на экране загрузки даже без VPN, а эмулятор не воспроизводит DPI
конкретного провайдера. Поэтому итоговую работу видео и Discord необходимо
подтверждать на реальном телефоне в проблемной сети — приложение больше не
выставляет это подтверждение автоматически.

## Сборка

Нужны JDK 17, Android SDK 35, CMake 3.22.1 и NDK 25.1.8937393. Клонируйте рекурсивно, затем:

```powershell
./gradlew.bat testDebugUnitTest assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Клонировать проект необходимо с зависимостями: `git clone --recurse-submodules`.
Задача `prepareHevSources` автоматически материализует upstream-симлинки на
Windows и применяет совместимую с Android NDK настройку errno для lwIP. Нативные
библиотеки локального DPI собираются из зафиксированных исходников. libbox и
TGWs JNI загружаются из закреплённых официальных артефактов с проверкой SHA-256;
их исходники, версии и инструкции указаны выше и в notices.
