# Local Route — Android MVP

Отдельное Android-приложение Local Route. Код Windows-версии в этот подпроект не
переносится и не изменяется.

## Архитектурное и лицензионное решение (зафиксировано до реализации)

`LOCAL_DPI` строится по схеме ByeDPIAndroid: Android `VpnService` создаёт только
локальный TUN-интерфейс, `tun2socks` направляет трафик устройства в локальный
SOCKS5-процесс, а DPI-стратегия применяется локальным процессом. Внешнего
прокси, VPN-сервера и передачи телеметрии в этом режиме нет. IP пользователя не
скрывается и трафик не шифруется дополнительно.

Вдохновляющий проект [ByeDPIAndroid](https://github.com/dovecoteescapee/ByeDPIAndroid)
— GPL-3.0 и использует ByeDPI (MIT) и hev-socks5-tunnel (MIT). Android-подпроект
Local Route поэтому выпускается под GPL-3.0-or-later. Вендорены как Git
submodules фиксированные исходники ByeDPI и hev-socks5-tunnel; JNI-граница
ByeDPI собрана по аудированному GPL-референсу актуального `master` ByeDPIAndroid
(`43db0955de687d43f9473374dc7c5548eaa55359`) и версии 1.2.0, а `NativeTunnelBridge` остаётся
точкой подключения tun2socks. Notices, SHA и ссылки на исходники находятся в
`app/src/main/assets/licenses/`.

`SECURE_TUNNEL` — отдельный интерфейс и конфигурация для будущего собственного
сервера пользователя; подключений в MVP нет.

## Открытый код и лицензии

Исходный код Android-версии Local Route распространяется по лицензии
[GNU GPL-3.0-or-later](LICENSE). Репозиторий включает полный текст GPL и
уведомления о сторонних компонентах в
[`app/src/main/assets/licenses/`](app/src/main/assets/licenses/).

В реализации использованы и указаны следующие проекты:

* [ByeDPIAndroid](https://github.com/dovecoteescapee/ByeDPIAndroid) — GPL-3.0;
  его локальная VPN/JNI-архитектура была изучена и адаптирована.
* [ByeDPI](https://github.com/hufrea/byedpi) — MIT; исходники подключены как
  зафиксированный Git submodule.
* [hev-socks5-tunnel](https://github.com/heiher/hev-socks5-tunnel) — MIT;
  исходники подключены как зафиксированный Git submodule. Его вложенные
  компоненты и их лицензии также перечислены в notice-файле.

Для сборки или распространения APK необходимо сохранять эти notices, тексты
лицензий и доступ к соответствующему исходному коду.

## Модули пакетов

* `core` — профили, режимы и диагностика.
* `localdpi` — `VpnService`, foreground-уведомление и адаптер локального
  SOCKS/tun2socks-движка.
* `tunnel` — контракт будущего защищённого серверного туннеля.
* `data` — локальные SharedPreferences для последней подтверждённой стратегии.
* корневой Compose UI — тёмные русскоязычные экраны управления и диагностики.
* `licenses` — упакованные лицензии и notices.

## Ограничения

Режим применим лишь к обычным блокировкам DPI. Он **не** заменяет полноценный
туннель в сети с разрешённым списком сайтов. Не реализуется и не обещается
«маскировка Google под Яндекс»: для HTTPS это не надёжная локальная техника.
Telegram не является рабочим сервисом MVP. Android потребует явного согласия на
VPN. Автозапуск после перезагрузки не реализуется.

## Что работает в MVP 0.11

* Тёмный адаптивный интерфейс Jetpack Compose для YouTube и Discord с фирменным
  знаком desktop-версии и ссылками на Telegram/GitHub.
* Один Android-профиль на ByeDPI 13 той же зафиксированной ревизии, которую
  использует ByeDPIAndroid 1.2.0. Он основан на рабочей строке ByeDPIAndroid.
  Дополнительные пресеты будут возвращены только после реальной проверки.
* Пользовательская строка передаётся в ByeDPI без добавления скрытых флагов.
  Адрес `127.0.0.1:1080` берётся из штатных значений ByeDPI, как в
  ByeDPIAndroid. В частности Local Route больше не добавляет `--no-ipv6`.
* На первом этапе доступен один профиль, буквально совпадающий с рабочей
  строкой ByeDPIAndroid, вместо неподтверждённого набора пресетов.
* VPN-сервис использует жизненный цикл ByeDPIAndroid: один нативный ByeDPI
  event loop и один TUN-to-SOCKS worker на весь сеанс защиты.
* Автоматический сетевой тест отключён: он не может доказать работу YouTube и
  давал ложные сообщения об ошибке. Экран «Проверка» открывает выбранный
  сервис при включённой защите; подтверждение — реальное воспроизведение.
* Как в ByeDPIAndroid, VPN работает для всего устройства, а собственный пакет
  Local Route исключён, чтобы исходящие соединения локального SOCKS не попадали
  обратно в TUN. Выбор YouTube/Discord задаёт цели проверки, а не VPN allowlist.
* DNS внутри VPN не переопределяется. Это соответствует показанной рабочей
  конфигурации ByeDPIAndroid с полем DNS «Не указано» и не ломает сети, где
  публичный резолвер `1.1.1.1` заблокирован. IPv6 в MVP не перехватывается.
* Нативная цепочка запускается в порядке ByeDPIAndroid: сначала локальный
  `ByeDPI SOCKS5`, затем `VpnService` и `hev-socks5-tunnel`. Аргументы JNI
  остаются живы всё время работы нативного event loop.
* Постоянное Android-уведомление показывает активную стратегию и содержит
  кнопку остановки. Для Android 13+ приложение запрашивает разрешение на
  уведомления перед первым запуском.
* Кнопка «Добавить плитку в шторку» использует системный Android API. Плитка
  запускает/останавливает локальный режим; если согласия VPN ещё нет, она
  открывает приложение для его получения.
* Никакой телеметрии, аналитики, загрузки логов или внешнего fallback-сервера.

## Запуск и проверка на телефоне

1. Установите APK и нажмите «Включить защиту».
2. Разрешите уведомления и подтвердите системный запрос VPN. Значок ключа — это
   локальный `VpnService`, а не внешний VPN-сервер.
3. Откройте YouTube и запустите видео. При реальном успехе откройте
   «Проверка» и нажмите «Работает — сохранить». Если сервис не работает,
   нажмите «Не работает — остановить».
4. На экране «Управление» добавьте плитку Local Route в шторку. После этого
   сохранённый профиль включается одним нажатием.
5. При проблеме откройте «Технический журнал». Он хранится только в памяти
   приложения и никуда не отправляется.

На Android-эмуляторе проверены UI, согласие VPN, device-wide TUN, SOCKS5,
повторный запуск и уведомление. Заводская версия YouTube в используемом образе эмулятора
сама остаётся на экране загрузки даже без VPN, а эмулятор не воспроизводит DPI
конкретного провайдера. Поэтому итоговую работу видео и Discord необходимо
подтверждать на реальном телефоне в проблемной сети — приложение больше не
выставляет это подтверждение автоматически.

## Сборка

Нужны JDK 17, Android SDK 35, CMake и NDK 30. Клонируйте рекурсивно, затем:

```powershell
./gradlew.bat testDebugUnitTest assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Клонировать проект необходимо с зависимостями: `git clone --recurse-submodules`.
Задача `prepareHevSources` автоматически материализует upstream-симлинки на
Windows и применяет совместимую с Android NDK настройку errno для lwIP. Нативные
библиотеки собираются из зафиксированных исходников, а не скачиваются готовыми.
